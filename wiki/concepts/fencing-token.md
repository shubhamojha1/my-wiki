# Fencing Token

A **fencing token** is a monotonically increasing number generated by a lock service each time a client acquires a lock. The resource server rejects any operation with a stale token, preventing unsafe writes from clients that unknowingly lost their lease.

## How It Works

1. Client acquires lock → lock service returns **token = 33**
2. Client pauses; lease expires
3. Client 2 acquires lock → lock service returns **token = 34**
4. Client 2 writes to storage with token 34
5. Storage records last-seen token = 34
6. Client 1 resumes, writes with stale token 33
7. Storage rejects (33 < 34)

## Requirements

- **Strictly monotonically increasing** (not just unique)
- **Generated by the lock service**, not the client
- **Checked by the resource server**, not the lock service

## Sources of Fencing Tokens

| Lock Service | Token Source |
|-------------|--------------|
| [[ZooKeeper]] | `zxid` or znode version number |
| [[etcd]] | Revision number |
