# SHA-256

**SHA-256** (Secure Hash Algorithm 256-bit) is part of the SHA-2 family, standardized by NIST in 2001. It produces a 256-bit (32-byte) digest — the current default for file integrity and digital signatures.

## Characteristics

- **Output**: 256 bits (64 hex characters)
- **Collision-resistant**: No known practical collision attacks
- **One-way**: Computationally infeasible to reverse (preimage resistant)
- **Avalanche effect**: A single bit change in input changes ~50% of output bits

## Example

```
SHA-256("hello") = 2cf24dba5fb0a30e26e83b2ac5b9e29e1b161e5c1fa7425e73043362938b9824
SHA-256("hello!") = ce06092fb948d9af99c8be03e82c4d68de9a026d18b9a12c1d8c7d7c69f3d17b
```

Note: adding one character completely changes the digest.

## Use Cases

- **File integrity verification** — checksums for downloaded files, software packages
- **Digital signatures** — hash input before signing with RSA or ECDSA
- **TLS/HTTPS** — certificates use SHA-256 signatures
- **Bitcoin** — proof-of-work mining uses double SHA-256
- **Git** — (historically SHA-1; transitioning to SHA-256 for object hashing)
- **Password hashing** — as a component of PBKDF2 (with salting and iterations)

## SHA-2 Family

| Variant | Output | Use Case |
|---------|--------|---------|
| SHA-224 | 224 bits | Legacy interop |
| SHA-256 | 256 bits | Standard |
| SHA-384 | 384 bits | Higher security |
| SHA-512 | 512 bits | Highest security, faster on 64-bit CPUs |

## Performance

SHA-256 is implemented in hardware on modern CPUs (Intel SHA Extensions, ARM Crypto Extensions), making it extremely fast — often >1 GB/s for bulk hashing.
