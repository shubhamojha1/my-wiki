# Idempotency Key

A unique identifier (typically UUID) generated by the client and sent with each request to prevent duplicate processing.

## How It Works

1. Client generates unique key (e.g., `req_abc123`) for a logical operation
2. Server receives request with key
3. Server checks [[Deduplication Store]]:
   - **Key exists**: Return cached result without re-processing
   - **Key new**: Process request, store result, return response

## Use Cases

- Payment processing (Stripe, PayPal require idempotency keys)
- Order creation
- Any POST request where duplicates are harmful

## Implementation Details

- **Storage**: Redis, database table with unique constraint on key
- **TTL**: Keys expire after a time window (e.g., 24 hours) matching retry policies
- **Concurrency**: Use atomic "insert if not exists" or distributed locks to handle simultaneous requests
